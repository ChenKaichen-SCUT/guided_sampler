# 离线计分与证据边界

本文件解释输出字段，不改变预注册实验次数、阈值或晋级条件。

正式模型以完整宿主的事务收据为准：原公式合法、原变量完整投影、不同模型，并且 commit 完成时间严格小于 120 秒。数量会话另要求至多 20 个。原始状态字符串 `complete100` 是继承实现的通用数量完成标签；本轮真实上限是 20，报告用实际收据数量判断，不能据此声称完成 100 个。

官方脚本和精确计数适配器沿用冻结版本。每个样本先由官方求值，再由原式完整代入检查；指定目标另以独立记录的官方实际访问和值核对。指导因成本保护关闭后，在线覆盖字段可能为 null；最终覆盖仍由全部正式模型的离线官方结果计算，null 不当作零。每个模型的增量和时间 AUC 使用离线精确前缀。

等时间比较使用独立 time120 会话。严格 20 模型比较仅使用独立 n20_t120 且双方都完成 20 个的实例。其他数量不足的会话仍展示总量和共同前缀，严格 20 模型结果为 NA，不算平局或胜利。均值采用实例等权的精确覆盖百分点，不能以 AST 较大的实例加权。

覆盖分区沿用第五轮规则：G1 是双方首个模型都只有单侧观察、且双方语义目录均映射的 bit；G2 是其他初始单侧 bit；G3 是双方初始都未访问的 bit。G0 为初始已双侧覆盖，G4 单独保存双方初始观察不同的 bit。每个分区同时记录独有收益和独有损失，分区净和必须等于全式精确覆盖差。全会话、双方共有前缀以及可用的 1/3/10/20 前缀分别比较。

每次守卫交还以原生调用 ID、宿主查询 ID、完整 map 哈希及实际消费 map 哈希关联。日志保存守卫精确退出步、全局 best、最后改善步、初始化/重启数、RNG 哈希及 CPU/墙钟。宿主 deadline/cancel 原因与原生原因分列；进入宿主 CCSS 检查但未进入原生内核的调用也保留。

事件链里的“后续”是时间顺序，不是精确因果归因。每个交还之后直到下次交还的正式模型和新增 covered 采用不重叠分配，避免重复加总。后续查询总数等后缀指标可能重叠，不能求和当作新增产出。匹配会话的查询数、模型数和覆盖差另行展示。相同 seed 不代表同一内部状态，完整轨迹分叉后的耗时差不能称为精确节省。

最后全局改善的墙钟时间没有测量：搜索热路径只增加固定整数记录和检查。事件链保留该点的精确步号，并明确标记墙钟缺项。原生搜索计时、原生完整调用计时、宿主检查计时和进程 wall/CPU 是不同边界；不以一个替代另一个。新增 map/RNG 序列化仅发生在搜索热路径之外，其费用包含在宿主与进程总成本中，没有单独隔离日志开销的实验。

候选是否实施和是否晋级由已提交的预登记规则决定。单 seed 的有限诊断不构成统计稳定性或普遍优势证明。若未晋级，不以短会话成绩替代 900 秒或严格 100 模型结果，更不能声称超过完整 HighDiv。
