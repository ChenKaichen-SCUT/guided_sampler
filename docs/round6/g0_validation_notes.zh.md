# G0 验证记录

正式 G1/G2 开始前，Release 和 ASan/UBSan 分别通过 29 项继承回归、14 项守卫机制检查、通用异常分类检查，以及对第五轮保存文件的关闭行为逐字节比较。关闭行为比较包含原生决策、随机流、初始化快照、区间和模型，没有执行旧二进制。既有泄漏抑制文件保持不变。

所有预冻结失败及修正均保留：

- Release `guard_release_01` 的异常测试错误地假定超过 int64 的整数常量会在解析时抛出异常。实际 128 位原生路径可以处理该值并返回合法解。改为超过原生 128 位表示范围的合成常量后，得到明确的 `arith_unknown`。这项修正只改变测试输入。
- ASan `guard_sanitize_01` 的连续初始化测试直接构造纯布尔配方，暴露了既有 `reduce_vars()` 的 `use_pbs` 路径问题：以空 `_tmp_vars` 替换 `_resolution_vars` 后，构造仍按旧索引访问已不在有效长度内的存储，泄漏 64 个分配、共 16384 字节。失败源码与原始检测日志保留。测试改为整数 x∈[0,100] 与同一布尔子句集的混合配方；128 次原生初始化仍同时覆盖严格全局改善和无全局改善。没有修复或隐藏该既有纯布尔构造缺陷，没有添加泄漏抑制。它是已知适用范围限制，不能将其称为全输入正确性证明。
- Release 的最终机制记录为 `guard_release_03`，ASan 为 `guard_sanitize_02`。此前所有尝试保留，不覆盖或删除。
- 首次冻结脚本将构建生成的 Python 字节码误当成文本补丁，因 UTF-8 解码失败而停止；脚本改为排除编译产物。没有启动任何正式求解会话，也没有改变生产实现。

受控宿主测试证明停滞交还不产生 CCSS 模型，不更新 m_ls；后续 CDCL 能继续返回合法模型。原生 cutoff、算术异常、通用异常、宿主取消/截止与守卫原因分开记录。最后全局改善记录精确步号；热路径不读时钟，因此不伪造最后改善的墙钟时间。该时间点的墙钟字段在后续事件链中明确记为缺失。

“独立审计”指使用单独的只读脚本、冻结官方计分器及独立精确求值交叉核对，不代表另一个研究者或另一个代理完成审查。
