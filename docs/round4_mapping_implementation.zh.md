# M 阶段实现与核验位置

`include/round4/semantic_correspondence.hpp` 在不创建 AST 的前提下识别恰好两个互补闭界。两边必须具有相同 Int 项、相同精确常数和相反界向；OR 规则要求两个孩子分别有 NOT。支持孩子交换、常数换边和外层 NOT；严格界、不等上下界、不同项和不同类型不套用新规则。

`include/round4/a_shared.hpp` 是隔离的 R4 副本。识别后直接生成现有等式线性 IR，并合成极性；并未调用 simplify/check、恢复消元变量或推导变量域。原变量/内部 skolem、类型和符号种类沿用有类型声明 IR；内部辅助变量不按显示名字强配。

桥接层仍构建旧 Bool 自身/显式 t=c 支持规则，并仅在正式提交后更新单侧需求。增加原节点结构指纹、原对应极性和两侧观察状态，以支持离线机会复核。`GUIDED_R4_MAPPING_OFF` 仅用于正确性回归，不进入六项 M 运行。

`patch_round4_z3.py` 从冻结 R3 生成器构建新的源码树，加入映射漏斗和机会记录。真实内部表达式由 manager 所有的引用向量持有，在正常边界序列化，热路径只记录轻量身份及受限元数据。新增映射机会与真正建议分开：版本 0、版本大于 0、单侧需求、评分平分、配额、同相位、实际改变分别记录。窗口以外不为了统计而扩大规范化扫描，不能从未扫描推断不存在映射。原生未选择的原子亦不凭空声称被尝试。

Release/ASan 采用各自独立的 worktrees/round4_M_* 和 deps/round4_M_*。修改归档为 patches/round4/M；历史三轮代码、树、库和记录均保留。源码中最终相位仲裁仍为旧正向支持规则，没有 S 参考降级、block 评分或新 relevance。

独立审计从原节点字典、提交前 seen 掩码、实际内部 AST/声明和正式模型重算机会与结果。最多选取 16 个有声明身份依据的实际映射，在无 F 背景的原声明空间作 2 秒 XOR 检查；另预先规定最多 6 个新增映射需求，各检查 F+G 与 F+继承条件+G，每项 2 秒。先固定选择、后读取独立答案，不把答案或见证模型传给采样器。
