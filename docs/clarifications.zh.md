## 一、正式实验固定为64次，HighDiv只运行其中16次

每个实例执行两种**独立运行**：

| 模式 | 数量限制 | 时间限制 | 最终统计 |
|---|---:|---:|---|
| `time900` | **无数量上限** | 900秒 | 截止前全部正式模型的覆盖 |
| `n100_t900` | 100个不同合法模型 | 900秒 | 达到100时停止；否则保留实际数量与覆盖 |

四个配置全部使用 **seed=0**：

| 配置 | 实例数 | 预算模式数 | 正式会话数 |
|---|---:|---:|---:|
| 完整 HighDiv，共同编译与测量适配 | 8 | 2 | **16** |
| A-only | 8 | 2 | **16** |
| B-only | 8 | 2 | **16** |
| A+B | 8 | 2 | **16** |
| **合计** | | | **64** |

HighDiv 的16次运行完成后冻结模型、时间收据、二进制、依赖和输入哈希，后续只读取，不自动重跑。

**两个预算模式不能混为一个实验。** `time900` 的前100个模型可以作为补充前缀结果，但不能替代单独执行的 `n100_t900`。

还有一个源码中的具体陷阱：**上游 `-n 0` 不表示无限采样，而会直接返回。** 指引要求在基线和新方法的共同适配中增加明确的“无数量上限”表示，而不是直接传 `-n 0`。

## 二、A和B的实现边界已经固定

### 通道A：只调整已经存在的原子的相位

A不改变原生变量选择顺序，不增加理论约束，不移动整数赋值。

第一版只使用直接语义匹配，例如：

```text
原公式已有原子：x = 10
当前缺口：x的第1位尚未观察到1

可以提出：
当这个原子被正常选中时，优先尝试true。
```

同样，原布尔原子自身只观察到一侧时，也可以偏好另一侧。

但不能做下面的错误推断：

```text
x = 10 为false
    ⇒ x的第1位一定为0        // 不成立
```

A的主要新增函数包括：

| 新增函数或类 | 职责 |
|---|---|
| `AtomHintCatalog::build()` | 建立原布尔原子、显式常量等式与原bit目标的直接联系 |
| `on_demands_changed()` | 模型正式提交后增量更新相关分数 |
| `lookup_existing_atom()` | 对当前原生决策原子返回相位建议或“不介入” |
| `CoverageDecisionBroker` | 在唯一仲裁点决定本次使用原生选择、A还是B |

没有可靠匹配、原子未遇到、已经被传播赋值，或者存在特殊决策时，A不强行介入。

### 通道B：让精确观察目标成为普通可回溯决策

B处理A不能直接表达的目标。目标包含两部分：

```text
原AST节点确实被访问
    并且
指定bit取到缺失的一侧
```

整数位使用精确的常模关系表达，不把原始整数改成64位整数。例如第 `j` 位：

```text
P = 2^(j+1)
H = 2^j
r = mod(e, P)

希望该位为1：r >= H
希望该位为0：r < H
```

这里使用正模数的非负余数，因此负整数也能保持正确的低位语义；`2^64` 等常数必须用精确大整数构造。[SMT-LIB](https://smt-lib.org/theories-Ints.shtml)

**本版优先采用内部目标代理：让Z3认识目标表达式对应的布尔literal，再优先把它作为普通decision尝试为真。不能把目标直接断言为真。**

目标与其他条件冲突后，正常回溯可以放弃它。以下做法都被指引禁止：

```text
solver.add(goal)                  // 把目标变成必须满足
solver.check({goal})              // 本次检查必须满足目标
assert_and_track(goal, label)     // 不是我们要的可放弃偏好
```

B的新增函数包括：

| 新增函数或类 | 职责 |
|---|---|
| `ReachBuilder::reach()` | 翻译原AST短路访问条件，保留共享结构 |
| `TargetEncoder::make()` | 构造精确的Reach与bit目标 |
| `prepare_targets_at_safe_point()` | 在SMT内核安全边界内部化目标 |
| `suggest_B()` | 提供未赋值、尚未主动尝试过的目标literal |
| `end_check()` | 清理当次指导状态并输出诊断，不删除合法学习信息 |

原子内部化、relevance和实际取真是不同步骤，必须分别记录。上游确实提供了内部化、relevance及正常决策相关的内核接口，但它们的调用顺序仍需通过真实补丁测试验证，不能仅凭编译通过判断正确。 

## 三、避免与HighDiv相互干扰，最重要的是保留真实调用路径

指引不是要求把之前的几个补丁直接叠上去，而是从完整HighDiv建立独立的新工作副本。

### 保留HighDiv的原有能力

保留 `hybrid_sampling()`、原有预处理与模型恢复、CDCL与CCSS执行流程、LS模型形成的变量固定条件，以及HighDiv自己的随机数流。不把CDCL求解器替换成简化枚举器，也不新增完整模型阻塞。

新机制的接入结构是：

```text
LiaSampler / GuidanceBridge
    ↓
新增的solver专用指导元数据接口
    ↓
combined_solver按原有规则选择后端
    ↓
实际支持的SMT内核
    ↓
唯一的CoverageDecisionBroker
    ↓
正常传播、决策、冲突处理和回溯
```

### 不通过外层add或push/pop“顺便接入”

这是这次源码核对中最需要防范的一点。

HighDiv使用的默认求解器具有不同执行路径。`combined_solver` 中，`push()`、检查后继续添加assertion，以及非空assumptions等，都会影响incremental路由。**如果为了注册目标而不断从外层add、push/pop，就可能同时改变求解器执行方式，而不只是增加覆盖偏好。** 

所以第一版明确规定：

- 安装指导首先只是传递元数据，不能触发新的求解、push/pop或外层assertion。
- 在自然进入的持久SMT内核中启用指导。
- 不支持的tactic执行路径原样运行并记录，不能偷偷改成simple solver。
- 指导状态绑定具体solver，不能误装到同一context中的CCSS求解器。
- `off`模式不创建目标、不消耗新增随机数，并通过受控兼容性回归。

这意味着第一版可能不能指导每一次CDCL检查。**该限制必须实际统计，不能把“接口安装成功”当作“机制已经生效”。**

## 四、输出端必须隔离辅助变量，并保留完整覆盖语义

B会引入内部代理或其他辅助项，因此输出代码不能继续简单地把当前model中出现的所有声明都当作测试输入。

指引要求：

> **正式模型、样本去重和覆盖评估，只使用原始AST中实际出现的原始自由变量。**

辅助变量不能进入样本身份，也不能进入HighDiv的变量固定交换流程。否则可能出现：

```text
原变量完全相同，只有目标辅助变量不同
    ↓
被误认为两个不同样本
    ↓
100样本实验提前结束，比较失真
```

共同测量适配在HighDiv和新方法上采用相同的原变量输出与收据规则；新方法独有的目录、目标构造、覆盖反馈和指导日志成本，则由新方法真实承担。

观察状态仍严格遵循你的定义：

| 状态 | 指导行为 |
|---|---|
| 两侧未见 | 不指定取值 |
| 只见0 | 偏好1 |
| 只见1 | 偏好0 |
| 两侧都见过 | 不指定取值 |

首次观察计入 `new_observed`，补齐另一侧计入 `new_covered`。不因为一个合法不同模型没有新增covered就过滤它。

## 五、计分必须调用指定脚本，同时保留精确bit结果

每个正式运行都必须执行冻结版本的：

```bash
"$BASELINE_VENV/bin/python" "$FROZEN_METRIC" \
  -f "$ORIGINAL_SMT2" \
  -s "$FORMAL_SAMPLES" \
  -m wire_coverage
```

其中输入必须是**原始公式**，不是带指导目标的solver dump；样本文件只能按原始顺序包含截止前正式交付的模型。

源码中的 `wire_coverage` 最终输出只保留两位小数。因此指引另外要求一个**只读适配器**：导入同一个原脚本、使用同样的统计类，读取精确covered和total。它不能修改官方脚本或改变分母。

最终同时保存：

```text
官方原始输出：例如 12.83%
精确计数：covered / total
模型数量、完成状态、时间收据
逐模型新增观察和新增covered
```

还有一个重要检查：**脚本输出了覆盖率，不等于全部模型合法。** 原wire路径在求值过程中收集观察，外层并不会因为某个模型返回false就自动撤销该模型产生的统计，所以必须独立核对合法性。 

对于100样本模式，报告同时给出实际数量和是否完成100。双方都完成100时，才能写“严格相同100样本覆盖比较”；未完成者不能拿最后一个模型的覆盖冒充C100。

## 六、16路调度、日志和上传也已写进执行协议

### 调度

使用**16个逻辑CPU工作槽，空槽补位**，不改回每物理核只跑一个进程。

任务入队顺序固定为：

```text
HighDiv的16项
    → A-only的16项
    → B-only的16项
    → A+B的16项
```

前16项同步释放，之后按冻结队列补位；不根据结果输赢调度。记录实际CPU绑定、并发构成、CPU时间和退出状态。由于100样本任务会提前结束，报告不宣称各算法经历完全相同的瞬时负载。

采样期间不混入编译、独立审计、压缩或大文件推送。

### 调试记录

指引要求分别记录这条链：

```text
目标被选入窗口
    → A匹配或B编码
    → 成功绑定/内部化
    → 实际进入决策
    → 最终模型是否实现目标
    → 是否真的形成新增观察或covered
    → 完整成本是多少
```

未映射、未遇到、目标被放弃、后端不支持、预算退出等原因分开，不能全部写成“机制失败”。

### 上传

上传到 `ChenKaichen-SCUT/guided_sampler` 的内容包括新增代码、补丁、测试、冻结配置、运行计划、正式与失败结果、原始模型归档、官方计分输出、独立审计和中文报告。

构建目录、虚拟环境和凭据不上传。原始结果可无损压缩分片，但必须能从仓库实际恢复，不能只上传指向你电脑绝对路径的清单。推送后核对远端SHA，失败则如实报告。
