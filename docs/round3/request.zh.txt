这次安排的是**有限的原因诊断实验**，不再执行整套900秒性能比较，不重跑HighDiv，也不重新开启B。核心内容如下。

## 一、下一轮必须区分：到底是“没有改变”，还是“没有观察到改变”

对每一个被引导的目标，都应分别回答：

| 检查项 | 要回答的问题 |
|---|---|
| **内部赋值** | 这个原子是否按建议取值？之后有没有被撤销或重新赋值？ |
| **理论参与** | 该赋值是否真的进入了整数约束处理？ |
| **模型位值** | 最终整数模型中，目标表达式的这一位是否达到期望值？ |
| **实际访问** | 官方覆盖评测是否访问到了原AST中的这个节点？ |
| **新增覆盖** | 访问到期望值后，是否补齐了历史缺失的一侧？ |

最重要的修改是：**即使节点没有被官方评测访问，也单独计算它在完整模型中的位值。**

例如，历史上某位只见过0，现在希望1：

```text
情况A：
    最终位值仍是0。
    → 值没有达到目标。

情况B：
    最终位值是1，但该AST节点没有被访问。
    → 值达到了目标，访问路径没有达到目标。

情况C：
    最终位值是1，而且该节点被访问。
    → 真正命中了缺失观察，可以新增covered。
```

这三个结果对应不同的改进方向，不能全部汇总成“目标没命中”。

**纯值检查不能改变官方覆盖口径。** 未被访问的节点即使位值正确，也只记为“数值目标实现”，不更新正式seen状态。

## 二、先查convert：内部赋值为什么没有成为模型事实

这一项应当优先于修改算法。

现有独立审计中，有一个很明确的历史事件：

```text
convert，时间模式
query_id = 11
decision_id = 64

原生相位：false
建议相位：true
内部最终赋值：true
返回模型中的对应原子：false
记录中没有撤销该次assignment
```

因此，至少不能把所有失败都解释成“软指引被正常回溯放弃”。这个事件的差异究竟来自理论相关性、映射、模型恢复，还是记录方式，需要进一步检查。

### 要补齐的证据链

指引要求在少量被选中的事件上记录：

```text
实际内部原子及其正负号
    ↓
建议提交后的assignment及唯一token
    ↓
该原子的relevance变化
    ↓
是否进入等式处理或理论传播
    ↓
该SMT叶子实际导出的模型
    ↓
模型转换后交给HighDiv的模型
    ↓
原变量输出快照
    ↓
官方AST访问和bit观察
```

这里有两个实现细节非常重要。

### 1. 不能只监听算术求解器的一个回调

我重新核对了冻结HighDiv的 `context::propagate_atoms()`：

- 等式原子走 `add_eq()` 或 `add_diseq()`；
- 其他理论原子才调用 `th->assign_eh()`。

所以，只检查 `theory_lra::assign_eh()`，可能漏掉已经通过等式推理进入理论层的情况。指引要求同时跟踪等式／不等式处理及其他理论原子传播。

### 2. 不能为调试提前调用 `get_model()`

冻结源码中的 `context::get_model()` 可能触发 `mk_proto_model()`，它不是可以在任何决策时刻随意调用的纯读取函数。指引要求在**原程序本来就要生成、导出模型的位置**抓取证据，而不是在相位回调中额外取模型。

同时，必须记录最终模型来自哪个tactic叶子。某个失败叶子里的assignment，不能和后续另一个成功叶子的模型直接比较。

## 三、relevance是重要嫌疑，但不能提前认定它就是答案

Z3官方内部说明明确指出：relevancy过滤会决定哪些布尔赋值暴露给理论求解器。因此，**内部布尔原子有一个值，不一定意味着这个值已经成为最终算术模型必须兑现的条件。** [Z3 Prover](https://z3prover.github.io/papers/z3internals.html)

但本轮仍然需要验证，而不是直接修改：

```text
内部赋值为true、模型里为false
    ≠
已经证明是relevance导致
```

还可能是原子对应关系或极性错误、不同模型阶段混用、输出补全等问题。

### 需要区分两个完全不同的“相关性”

**求解器的relevance：** 这个原子是否需要参与理论求解。

**覆盖评测的Reach：** 官方短路求值是否实际访问这个原AST节点。

即使解决了第一项，也不自动解决第二项。因此，下一轮不应把“标为relevant”当作“保证新增覆盖”的修复。

### 只有证据支持后，才做局部对照

如果追踪确认：某个真实事件的建议没有进入理论约束，那么再对少量检查点做下面的对照：

| 诊断分支 | 本次相位 | 当前已有原子的相关性处理 |
|---|---|---|
| N0 | 原生相位 | 不改变 |
| A0 | A建议相位 | 不改变 |
| N1 | 原生相位 | 仅对该现有原子做受控局部激活 |
| A1 | A建议相位 | 与N1相同的局部激活 |

这可以分开回答：

**是“让原子参与理论”就有帮助，还是在参与理论以后，“按缺失bit选择相位”还有额外帮助？**

这只是条件触发的诊断实验。它改变了相关性处理，不能冒充第二轮原封不动的A；也不能全局关闭relevancy、强行保留相位，或重新内部化一批B目标。

## 四、还要检查：我们想改变的bit，在当前求解条件下到底能不能改变

这是前两轮仍缺少的一个关键区分。

假设：

```text
原公式允许 x=0 或 x=10。
历史只观察到 x=0。
希望 x 的第1位取1。
```

从原公式看，这个目标可以实现；但如果当前HighDiv调用恰好继承了固定条件：

```text
x=0
```

那么这次调用就不可能实现该目标。

此时：

- 相位接口可能完全正确；
- 理论传播可能完全正确；
- 求解器放弃目标也完全正确；
- 失败来自**本次查询的固定条件**。

因此，下一轮需要对少量选定目标进行独立检查。

### 独立检查要分层

用 `F` 表示原公式，`Aq` 表示当前HighDiv原有的固定条件：

| 检查 | 目的 |
|---|---|
| `F + 目标位值` | 位值本身是否可能 |
| `F + 访问条件 + 目标位值` | 官方可观察目标是否可能 |
| `F + Aq + 访问条件 + 目标位值` | 当前HighDiv固定条件是否允许 |
| `F + Aq + 建议原子方向` | 当前建议的这条实现方式是否允许 |
| `F + Aq + 建议方向 + 目标位值不成立` | 检查“这个原子方向支持该bit”的规则有没有反例 |
| `F + Aq + 建议方向 + 目标节点不访问` | 检查动作是否缺少访问保证 |

**这些是独立诊断求解，不是往采样器里重新加入硬目标。** 答案不反馈给在线算法，不实现不可达缓存，也不改变覆盖分母。

如果独立检查给出SAT，就保存完整合法见证，再用官方观察器确认它真的命中该位。这样至少能区分：

> **目标确实可行，但A没找到；还是当前目标／当前固定条件本来就不允许。**

所有Unknown继续保留为未知，不加长时间直到得到想要的答案。

## 五、两个主实例继续查映射，但不再只统计接入次数

SMT_random和SMT_real没有实际改相位，所以它们与convert的问题不同。下一步应保存少量真实未匹配原子，判断它们属于什么情况，而不是先扩大64次窗口。

需要区分：

| 未匹配原因 | 对设计意味着什么 |
|---|---|
| 只是等号换边、极性或直接线性规范化遗漏 | 属于实现修复 |
| 原生消元替换后才能对应原变量 | 需要沿预处理来源建立语义映射 |
| 辅助布尔定义或理论生成原子 | 不能直接当作原AST节点，需要理解它控制什么 |
| 原子可以映射，但与当前缺口无关 | 当前机会没有覆盖价值 |
| 当前证据不足 | 保留未知，不能随便绑定 |

例如：

```text
原公式有 x=y+1。
原式原子是 x<=3。
内部处理的是 y<=2。
```

两者依赖原等式才对应，不是简单改写一个字符串就能建立联系。需要读取实际预处理替换，而不是猜测。

**这一步的目的，是判断A缺少的是工程映射，还是缺少能够影响目标bit的操作能力。** 两者的后续策略完全不同。

## 六、下一轮的运行范围

完整指引已经把实验限制为以下规模：

| 阶段 | 范围 |
|---|---|
| 旧数据复核 | 全部旧建议和支持目标，只读 |
| 新短轨迹 | convert、SMT_random、SMT_real，各运行“只观察”和“执行A”两种模式，共6次 |
| 短轨迹上限 | 每次最多60秒；convert最多32次CDCL查询，其余各最多8次 |
| 独立目标检查 | 最多12个见证，每个最多8次检查，每次最多2秒 |
| 未映射核验 | 每个主实例最多8个代表原子 |
| 条件原因干预 | 最多6个检查点，每个最多4个子运行、每个5秒 |
| 新900秒性能实验 | **不执行** |
| HighDiv基线重跑 | **不执行** |

诊断可以使用16个逻辑线程并行独立任务，但不与编译、消毒器、压缩同时进行。深度诊断的耗时也不能拿来宣称采样性能优劣。

对于真正的同状态分支对照，指引还特别禁止直接对当前带watchdog线程的正式进程调用 `fork()`。需要单线程诊断程序和外部超时管理；无法安全实现时，就明确降级为“相同查询、不同历史状态”的对照，不冒称同状态因果实验。

## 七、根据原因，才能决定怎样让目标bit真正改变

下一项策略应该由诊断结果决定，而不是一次把所有方向加进去：

| 被确认的主要原因 | 下一项应研究的策略 |
|---|---|
| 原子／极性／模型关联错误 | 修复正确性，不新增启发式 |
| 建议只改变布尔赋值，没有进入理论 | 有界、可撤销的理论参与引导 |
| 位值已实现，但节点未访问 | 先协调访问路径，再引导数值 |
| 原式允许，但当前固定条件阻塞 | 有依据地释放少量固定条件 |
| 当前建议方向不可行，但目标有其他实现方式 | 更换实现该目标的原子或分支，不反复追同一路径 |
| 目标本身不可行 | 后续再考虑宏观摘要或可靠排除 |
| 映射正确、目标可行、传播正常，却反复被撤销 | 分析冲突与协调成本，再考虑更强的可放弃指导 |

**这一轮最重要的产出，应是一条能逐步核验的解释：目标是什么、当前动作控制什么、理论层是否接受、最终模型为何取这个值、官方为什么观察到或没有观察到。**

如果得到正例，就保存完整的：

```text
原本缺失的bit
    → 实际软相位操作
    → 理论约束生效
    → 返回合法模型
    → 官方访问到期望位值
    → 新增covered
```

如果没有正例，但明确查到目标不可行、固定条件阻塞或A缺乏相应操作能力，也已经足以指导下一项设计，不能为了得到正例继续增加预算。
