# D3 条件干预的边界

D0–D2 完成后，D1 中存在最终 token 未观察到直接传递、但最终内部赋值与实际 M_leaf 不同的事件。按冻结顺序取最早 6 个检查点。D2 的 12 个见证在当次 F+Aq 下都无法实现建议方向；这不构成开启线上可达性过滤、B 或追加性能实验的理由。

D3 使用独立的 `round3_micro` 源码、库和程序，D1 的 Release/ASan 库与二进制保持冻结。只复建原 F、原 Aq、原覆盖快照，结果一律叫 `same_query_not_same_state`。历史学习子句、相位缓存、CCSS 交换没有复制。原采样 Session 有 watchdog，原生 Z3 的有时限调用还可能创建计时线程；这里没有经过验证的单线程历史进程快照，因此完全不调用 fork。每个子进程由外部父进程实施 5 秒截止，同时给原生 check 设置扣除初始化后的剩余额度。

原生 `context::decide()` 在调用 A 相位钩子之前已经 `push_scope()`。`context::mark_as_relevant(existing_var)` 调用原生 relevancy propagator。`relevancy_propagator::push()` 保存 relevant_exprs 与 trail 的界限，`pop()` unmark 并 undo；`context::pop_scope_core()` 实际调用这条撤销路径。因此 N1/A1 只使用这个既有接口，不直接改内部标志。

四个单元在同一 CPU 上顺序执行。N0/A0 不激活相关性，N1/A1 对本次已存在、已内部化且尚未赋值的原子激活；随后调用正常 propagate。若传播已经赋值、冲突或取消，停止本次人工相位步骤并交还原生搜索。不加断言，不调用 internalize，不改变候选变量，不全局设置 relevancy=0，不强行保持相位。若 native variable 尚未赋值，在交还前按既有 case-split queue API 归还候选。

每个进程最多触发一次干预，关闭其余 A 建议。只在前 64 个普通原生决策中寻找该已有原子的确切打印表达和键；没有遇到就记录未重现，不改候选、不延长窗口、不追加运行。与历史同 query/同原子不等于同搜索状态。

记录激活前后相关性、变量/断言数、scope、trail、原生相位、请求相位、实际相位、传播抢先赋值/冲突、激活与传播耗时、进程线程数，以及检查点之前的 RNG/原生决策日志长度。相位之外的 N1/A1 相关性干预单独命名，不能被描述成“只补日志的 A”。这些新动作的次数来自 `D3_mark_as_relevant_calls` 和 D3 事件；原 A 的旧固定零计数不作为 D3 纯只读证明。

固定玩具正例先验证四单元能够遇到真实候选、保持变量及断言不变，并分别执行期望的激活操作；它不计入 6 个真实检查点，也不作为真实实例有效性的证据。真实检查点即使没有遇到，也保留全部四单元结果。所有模型只用于诊断，绝不进入正式样本或覆盖性能统计。
