# 成本修复实施契约

本轮固定基点 ae6da89e16be99142b7402fe6f0bccfb87e19893。只做共同诊断、数值/LineTerm 复用、语法依赖反向索引及等价 oracle 编码共享；不改方向、候选、配额、保护、官方观察或原生机制。三配置均从同一原数据冷启动，无新的真实采样。

共同仪表使用固定大小阶段数组，析构不分配、不抛异常。时钟只在阶段作用域边界读取；AST 循环只增加计数。预算检查原有位置保留，新增独立阶段循环也检查预算，绝不减少检查频率换速度。为区分系数与依赖开销，旧逐节点依赖构造与仿射系数构造分为两个按原 postorder 的独立 pass，依赖和系数内部操作顺序保持；所有配置共用这层仪表。方向处理前建立 not_started/incomplete 槽，异常不会抹掉在途方向。未完成不是空域或不可达。

预登记缓存选择：每个 anchor 从空数值缓存开始，不预填原生观察。只替换原不变子项的 value-only 调用，不用表达式数值替换仿射点积。仿射常数沿用旧系数次序并按 anchor 复用；LineTerm 在当前完整方向上下文内复用。缓存没有 seen0/seen1/Reach。Shared 的父边闭包保留完整语法依赖，包括 x-x 和未选分支，不按代数抵消删观察点。

离线采用流式事件记录。候选与元数据构造、编码、写入纳入相应阶段；成本记录本身的序列化/写入另列 record_tails，并扣除后续可选余额。末尾总结记录不可能自测自己的最终写入，完整进程 CPU/墙钟由父进程 wait4/pidfd 计量并报告，不把尾部或输入解析成本当免费。

Legacy 三个诊断 worker 必须先于两项成本修复执行；它们的源文本和二进制 SHA 单独冻结。后续六探针和 39 条主/补充序列使用同一个最终 Release 构建，固定物理核 0，顺序执行，不与编译、压缩、上传或 oracle 并行。较宽探针不进入生产式历史或主覆盖表。随机分量限制保持 64/128/4096，预期仍有 10 个超限分量，无秩计算则标 rank_unknown。

OracleLegacy 与 OracleShared 共享重型导入之前建立的阶段日志、3 秒冷案例、2 秒最多一次 check。SMT2 完整导出仍在 check 前且计费。只把截止内完成且独立验证的见证计为交付。父进程强制退出时保留最后有效阶段，不凭 check_attempt 推造 solver 内部状态。
