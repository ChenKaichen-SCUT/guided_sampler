# 第四轮冻结执行计划

从 fa68a9996a48cc2251ab2b8d9315da44606825af 创建独立分支 round4-mapping-soft-reference，按完整[第四轮指引](round4/execution_guide.zh.md)实际实现、验证、实验和上传。

M 仅增加两类精确互补界门等价映射，保留原 HighDiv 继承 assumptions、旧正向评分、原生选择/relevance/CCSS、64 窗口和 4 配额。必须单列版本 0 映射、版本大于 0 的真实单侧需求、有效建议、最终纯值和官方观察。测试与 Release/ASan/UBSan 通过后冻结实现，仅执行固定的六次短会话，独立审计并提交结果后才实现 S。

S 将来源明确的 m_ls 继承值放入部分参考 sidecar，不生成新等式原子；原公式与真正外部 assumptions 继续硬约束。S_ref 与 S_cov 共享新宿主和自然路由；S_cov 唯一区别是按 (support, -block) 仲裁覆盖、再参考、再原生。支持与避免直接阻塞分别记录；已有赋值不被反转；保持原生正常传播和回溯，不加入 relevance 干预。

固定计划见 configs/round4.json 和 manifests/round4_short_plan.json。每阶段 convert 两模式各最多 32 次 CDCL，两个主实例各模式最多 8 次，每会话最多 60 秒，全部 seed=0、CPU 0 顺序执行。测时不与编译/消毒器/审计/压缩重叠。模型接纳和官方覆盖不变，参考改相位也纳入 45 秒显式及整查询暴露保护。

M 未产生真实需求时不扩规则、不放宽窗口。第三轮四个 F+G 可行且被继承条件阻塞的见证仅供离线验收，新代码不读取 oracle 答案/模型。任何无效映射、Unknown、重复、零命中和失败均保留。不会重跑冻结 HighDiv、追加 seed、开启 B、构造模目标代理、加入数值移动/域分析/MaxSMT，亦不启动 900 秒矩阵。

最终报告判断的是可行目标是否仍被自行硬固定，以及 S_cov 是否比同宿主 S_ref 更常取得可核验观察；相位次数仅为过程计数。完整证据无损归档、逐成员恢复校验，非强制推送并核对远端 SHA。

用户已明确消除第 5.3/7 节的配额歧义：覆盖建议每次外层 check 最多 4 次；参考偏好可以在前 64 个普通决策中使用，不消耗覆盖配额。覆盖与参考的实际相位改变均计入同一显式成本及整查询暴露保护。确认记录见 manifests/round4_quota_clarification.json，早于 S 实现和实验。
